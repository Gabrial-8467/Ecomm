# Security Architecture & OWASP Alignment Guide
## Apex Retailers Single-Owner E-Commerce Platform

### 1. Threat Modeling & Core Defense Mechanisms

| OWASP Top 10 Risk | Platform Countermeasure |
| :--- | :--- |
| **A01: Broken Access Control** | Role-based authorization middleware (`requireRole([ADMIN, STORE_MANAGER])`). Resource-ownership guards on orders, addresses, and customer profiles preventing IDOR vulnerabilities. |
| **A02: Cryptographic Failures** | Passwords hashed using `bcrypt` (10 salt rounds). Sessions signed via cryptographically random secrets. Transmission strictly over HTTPS. All Razorpay signatures verified server-side with HMAC SHA256. |
| **A03: Injection** | Full parameterization of SQL queries via Prisma ORM. No raw string interpolation into database statements. |
| **A04: Insecure Design** | Server-side price recalculation (clients never submit or dictate item prices or GST rates). Atomic inventory deduction locks stock inside transactions. |
| **A05: Security Misconfiguration** | Helmet enabled with strict Content Security Policy, HSTS, X-Content-Type-Options: nosniff, Frameguard, and XSS filter. |
| **A06: Vulnerable Components** | Dependencies locked and scanned via npm audit. Mutually tested package versions. |
| **A07: Identification & Auth Failures** | Strict rate-limiting on authentication endpoints (`authRateLimiter`). HttpOnly, SameSite cookies to mitigate XSS session hijacking. |
| **A08: Software & Data Integrity** | Webhooks from Razorpay verified with cryptographic secret before triggering state changes. |
| **A09: Security Logging & Monitoring** | `AuditLog` captures sensitive administrative operations (price updates, inventory write-offs, order cancellations, and refunds). Morgan logs HTTP requests without dumping passwords or payment secrets. |
| **A10: Server-Side Request Forgery** | External media downloads and uploads restricted to Cloudinary SDK or verified origins. |

### 2. Payment Security Rules

1. **Zero Card Storage**: Raw credit/debit card numbers, CVVs, and expiry dates are never ingested, handled, or stored by the server. All card entry occurs within Razorpay's PCI-DSS Level 1 compliant iframes.
2. **Double Verification**: An order is marked as `PAID` exclusively after verifying the HMAC SHA256 signature generated by `crypto.createHmac('sha256', secret).update(order_id + '|' + payment_id).digest('hex')`.
3. **Idempotency**: Webhook events and payment verification API calls enforce unique idempotency keys to completely eliminate duplicate order captures and double debits.
